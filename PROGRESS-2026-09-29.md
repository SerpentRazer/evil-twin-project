# Progress — 2026-09-29

Work done today on `evil_twin_detect.py` (Kali attacker/detector box).

## Goal
Feed the M4 browser dashboard (jellyfish) and get a live, colored network list
in the Kali terminal, with evil twins flagged in red.

## Architecture (agreed)
```
Kali detector  --UDP JSON push-->  receiver on M4 (M4_IP:9999)  -->  browser dashboard
```
- Transport: **UDP push**, fire-and-forget, port **9999**.
- `baseline.json` = known-good reference (learned once). Copy to M4 as seed inventory.
- Live inventory + alerts flow over UDP.
- **Receiver on M4 is Raz's job**, not built here.

## What was added to evil_twin_detect.py

### 1. UDP sender (blank IP until dashboard is ready)
- Reads `ET_M4_IP` (env). **Left blank on purpose** — script runs and prints
  normally, just skips sending. Bind later with no code change:
  ```bash
  export ET_M4_IP=192.168.x.x     # optional: export ET_M4_PORT=9999
  ```
- `send_udp(msg_type, **fields)` — no-op while IP unset.

### 2. Six UDP message types (each has `type` + `ts`)
- `evil_twin`   — new BSSID cloning a known SSID
- `rssi_anomaly`— known BSSID seen outside its learned signal corridor
- `deauth_flood`— burst of deauth frames
- `karma`       — one BSSID answering many SSIDs (Pineapple-style)
- `heartbeat`   — every 5s, "detector alive"
- `inventory`   — every 3s, full live AP list (drives the dashboard list)

### 3. Live terminal table (redraws every 3s)
- Shows **every AP on air** (not just alerts). This is the list Raz couldn't
  see before — it lives here now, not just in baseline.json.
- **Evil twins shown in RED**, sorted to the top. Other 3 alert types go to a
  "recent alerts" tail at the bottom.
- Old big banner blocks removed (screen redraws each cycle).

### 4. Relative-RSSI corroboration (added to evil_twin check)
- When a twin is flagged, compares its signal to the real AP's loudest learned
  RSSI. If twin is >= `RSSI_TWIN_LOUDER_MARGIN` (12 dB) louder -> adds a reason
  line + bumps confidence to HIGH. Rides along in the `evil_twin` UDP `reasons[]`.
- Deliberately **relative, not absolute** (avoids false alarms from nearby real APs).

## Key behavior Raz confirmed / learned today
- Detector only flags a **new BSSID cloning a name already in baseline.json**.
  That's why the Dell hotspot named `PRV_GUEST` (in baseline) got flagged, but
  the iPhone hotspot (name not in baseline) did not — correct behavior.
- **Must learn a clean baseline first** (real APs only, no attacker), else the
  fake gets saved as legit:
  ```bash
  sudo python3 evil_twin_detect.py --learn 60   # clean environment
  sudo ./start-detector.sh                        # then watch
  ```

## Tuning knobs (top of file)
- `INVENTORY_INTERVAL = 3`      redraw + inventory push cadence (s)
- `RSSI_TWIN_LOUDER_MARGIN = 12` lower = more sensitive
- existing: `RSSI_CORRIDOR_MARGIN`, `DEAUTH_*`, `PROBE_*`, `MIN_BEACONS_NEW`
